# debbaweb.it

Personal website of Andrea Debernardi, built with [Next.js](https://nextjs.org/) (pages router), Tailwind CSS and `next-g11n` for Italian/English content.

## Getting started

```bash
pnpm install
pnpm dev
```

Open [http://localhost:3000](http://localhost:3000).

| Script | What it does |
| --- | --- |
| `pnpm dev` | Development server |
| `pnpm build` / `pnpm start` | Production build and server |
| `pnpm typecheck` | TypeScript check |
| `pnpm lint` | ESLint |
| `pnpm test:a11y` | axe-core accessibility check against a running server (`BASE_URL`, default `http://localhost:3000`) |

Project pages call the GitHub API at build time. Set `GITHUB_TOKEN` to avoid the unauthenticated rate limit.

## Recent GitHub work

The first home tile shows up to three recently active public repositories, with brief Italian and English summaries generated by Claude. Project names and icons from the site catalog take precedence. For other projects, Claude derives a readable name from the README title and introduction and selects an icon from a fixed set based on the project purpose. Catalog projects without an image icon also use the AI-selected icon; icons appear beside the name. Projects listed in `src/data/projects.ts` link to their localized detail page and have a separate GitHub link; other projects link directly to GitHub. Repository matching uses both owner and name, case-insensitively. The generator considers the latest 300 public events within 30 days, including authored commits and pull requests in other owners' repositories. It ignores stars, forks, private events and other authors' work. Claude receives commit subjects and PR titles for the summaries, plus public repository descriptions, topics and up to 4,000 characters from the README introduction to identify the project name and icon. Patches and source files are never sent.

### Setup on GitHub and Vercel

1. In this repository's **Settings → Secrets and variables → Actions**, add the repository secret `ANTHROPIC_API_KEY`. Optionally set the repository variable `ANTHROPIC_MODEL` to a model available to your Anthropic account (default: `claude-haiku-4-5-20251001`). The workflow uses GitHub's built-in `GITHUB_TOKEN` for reading public activity and publishing the snapshot.
2. Merge the workflow into the default branch, enable Actions and allow the workflow to write repository contents. Run **Actions → Update GitHub activity → Run workflow** once to populate the tile immediately.
3. Deploy the site to Vercel as usual. The default snapshot repository is `debba/personal-website`; for a fork, set the Vercel environment variable `GITHUB_ACTIVITY_REPOSITORY=owner/repository`. This repository and the `github-activity` branch must be publicly readable. The snapshot branch includes its own `vercel.json` with deployments disabled, so data updates do not create preview builds.

The workflow runs at **00:17, 06:17, 12:17 and 18:17 UTC**, independently of visits. GitHub may delay scheduled jobs, and automatically disables schedules in public repositories after 60 days without repository activity; monitor Actions and re-enable the workflow if necessary. This uses GitHub Actions scheduling because Vercel Hobby's native cron jobs only support daily runs. No Claude key, database or cron secret is required in Vercel.

The validated bilingual snapshot is committed to a separate `github-activity` branch. The site reads it using Next.js ISR with a five-minute revalidation window, so a new snapshot appears after the next successful page regeneration, without a deployment. No AI calls happen during page builds or visits. Unchanged activity reuses its summaries; a changed input makes one Claude call for all three projects. Generation failures leave the last snapshot intact, and page refresh failures retain the last successful page. Before the first snapshot, a short introduction and GitHub profile link are shown. The displayed update date is the last successful activity check.

For local development on Node 22.18 or newer, copy `.env.example` to `.env` and fill in `ANTHROPIC_API_KEY` (optionally add `GITHUB_TOKEN`). Start `pnpm dev` and open the home page: the server generates the first snapshot automatically and reuses `.cache/github-activity.json` for six hours. The first visit may take longer while GitHub and Claude respond. To refresh manually, run `pnpm activity:update`. Both `.env` and `.cache/` are ignored by Git. Failed refreshes retain the previous local snapshot and retry after five minutes. Production still reads the published snapshot and requires the GitHub Actions secret configured above. Do not put keys in `NEXT_PUBLIC_*` variables. `pnpm test:activity` exercises filtering, bilingual validation, reuse and failure preservation with mocked APIs.

## Content

- Pages: home (bento overview), `/projects`, `/projects/[slug]`, `/about` (bio, services, activities, customers) and `/contacts` (direct contacts and form). The home page is a bento grid of tiles (`src/components/home/`). Tile spans in `src/pages/index.tsx` are tuned so every row is full at 4 columns; check the layout when adding or removing tiles.
- `HOME_PROJECTS` in `src/data/projects.ts` picks the projects shown as home tiles; `DOCK_PROJECTS` picks the ones in the dock tile.
- Open source projects live in `src/data/projects.ts`; images go in `public/images/projects/{cover,icon}/`. Animated GIF covers need a `still` frame, shown when the visitor prefers reduced motion and in the project grid.
- Translations live in `src/i18n/dictionary.ts`.

On the home page, Next.js selects Italian or English from the browser's `Accept-Language` preferences, falling back to English when neither is supported. Language links in the header let visitors switch manually; explicit locale URLs are respected.

## Appearance and accessibility

Colors and the Urbanist typeface follow the tabularis website. Colors are CSS tokens in `src/styles/globals.css`, exposed to Tailwind in `tailwind.config.js`. The same file defines the shared type scale (`page-title`, `section-title`, `tile-title`, `tile-label`, `tile-text`), tiles (`tile`, `bento`) and controls (`btn-*`, `segmented`); use them instead of ad hoc styles; keep the explicit dark palette and the automatic dark media query in sync.

The header offers Light / Dark / Auto. Auto follows `prefers-color-scheme`, including live system changes. The `debbaweb.theme` preference is stored locally, and if storage is blocked the site falls back to the device theme. An inline head script applies the stored preference before first paint, so the page never flashes the wrong theme.

The site includes a skip link, visible focus indicators, a mobile menu that closes with Escape and returns focus, labeled form errors, reduced-motion and forced-colors support, still frames for animated covers, and touch targets of at least 24px.

CI (`.github/workflows/ci.yml`) runs typecheck, build and `pnpm test:a11y`. The check covers home, projects, project pages, about, contacts and the 404 page in both languages, light and dark themes, and at 1280px and 320px widths. It applies the axe-core WCAG 2.2 AA rules plus best practices, and also fails on horizontal overflow or a theme that was not applied. Automated checks supplement keyboard, zoom and screen reader testing; they do not replace it.

## Project details and media

`src/data/project-details.ts` contains curated Italian and English platform labels, technologies, use cases, features and galleries for each project. Entries match the `github_name` in `src/data/projects.ts`. The project index shows full short descriptions and technology labels; individual pages show the full details.

Keep features aligned with the public repository documentation. Store original screenshots and videos in `public/media/projects/<slug>/` and record their sources in [the media manifest](public/media/projects/SOURCES.md). Videos need an MP4 source, a still poster and a descriptive caption. Current demos are silent, start manually and use `preload="none"`. Tabularis opens its gallery with the overview video.

Screenshots open in a modal gallery. Visitors can use the previous/next buttons or arrow keys to browse, and Escape to close. Media captions are translated alongside project descriptions.

Project pages always expose GitHub and a website link, or a clearly labelled documentation link when no dedicated site exists. These destinations are curated in `project-details.ts`, so API rate limits do not remove navigation.

With the site running, `pnpm test:projects` checks mobile/desktop layouts, both themes, automated accessibility, modal keyboard navigation and focus restoration, video playback, every project’s links, landscape layout and 200% text. Set `BASE_URL` to target another port and `CHROMIUM_PATH` to use a system Chromium installation.

The home dock uses `DOCK_PROJECTS` for featured open-source projects. `src/data/daily-work.ts` separately lists Emailchef and turboSMTP as professional products, with their official websites and dedicated descriptions.
